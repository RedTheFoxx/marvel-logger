## ClassDef MarvelLoggerBot
**MarvelLoggerBot**: The function of MarvelLoggerBot is to act as a Discord bot client that coordinates game tracking, user registration management, and sentiment logging while handling slash command registration and synchronization.

**attributes**: 
· tracker: An instance of TrackerScraper responsible for scraping and managing match data.
· registrations: An instance of RegistrationStore used to persist and retrieve user registration records.
· feels: An instance of FeelsStore utilized for storing and retrieving sentiment or reaction data.
· tree: An app_commands.CommandTree object that manages the bot's slash command definitions and execution flow.

**Code Description**: 
MarvelLoggerBot extends discord.Client to provide a structured implementation of a Discord bot. The constructor initializes standard Discord intents, assigns the injected tracker, registrations, and feels dependencies as instance attributes, and instantiates an application command tree. The setup_hook method is automatically triggered by the discord.py framework during initialization. It sequentially initializes the registration and feels data stores, starts the background tracker service, and registers five core slash commands: stats, register, unregister, match, and feels. Command synchronization behavior is conditional: if a DISCORD_GUILD_ID environment variable is defined, commands are copied from global scope to the specified guild and synchronized locally; otherwise, they are synchronized globally across all servers where the bot is present. The close method ensures graceful resource termination by stopping the tracker before invoking the parent client closure. The on_ready event handler logs a confirmation message containing the bot's username and user ID upon successful authentication and connection to Discord. Within the project architecture, this class is instantiated in the main application entry point, which constructs the required dependency instances and passes them via dependency injection before executing the bot with a provided Discord token. This design decouples the bot's core logic from external data sources and scraping mechanisms while centralizing initialization and runtime execution in the application root.

**Note**: 
The class requires valid DISCORD_TOKEN and optionally DISCORD_GUILD_ID environment variables to operate correctly. Command synchronization scope depends entirely on the presence of a guild ID, so environment configuration must be verified prior to deployment. The main entry point explicitly passes log_handler=None during bot execution to prevent discord.py from overriding custom logging configurations. Background scraping tasks are managed through the tracker dependency and must be properly terminated via the close method to avoid resource leaks or incomplete data states.

### FunctionDef setup_hook(self)
**setup_hook**: The function of setup_hook is to orchestrate the asynchronous initialization of database stores, external API scrapers, and Discord slash commands during bot startup, followed by command synchronization based on deployment configuration.

**parameters**: 
· self: The instance of the MarvelLoggerBot class that manages the bot's lifecycle, dependency injection, and application command tree routing.

**Code Description**: This method serves as the central initialization coordinator for the application, executing a strict sequential setup phase to guarantee all subsystems are operational before handling user interactions. It begins by asynchronously initializing two SQLite-backed persistence layers: `registrations` handles Discord-to-Tracker.gg username mapping storage and quota enforcement, while `feels` manages persistent match rating feedback and historical season records. Both initialization routines offload synchronous file I/O and schema execution to background thread pools via `asyncio.to_thread`, preventing event loop blocking during database preparation. Next, the method activates the `tracker` component by invoking its startup routine, which configures and launches an asynchronous stealthy web scraping session tailored for Tracker.gg interactions, including browser fingerprinting, timeout configuration, and rate-limit cooldown setup. 

Following subsystem readiness, the method registers five distinct slash commands (`/stats`, `/register`, `/unregister`, `/match`, `/feels`) by injecting the previously initialized stores and scraper instances as dependencies. This dependency injection pattern ensures each command handler receives direct access to the necessary data retrieval, validation, and persistence logic without tight coupling. The registration process binds these commands to `self.tree`, which acts as the central routing registry for Discord application commands. Finally, the method determines the deployment scope using the external `DISCORD_GUILD_ID` configuration variable. If a guild ID is provided, it copies global command definitions to that specific server and synchronizes them locally for immediate availability; otherwise, it registers and syncs the commands globally across all servers where the bot is present. Throughout this workflow, structured logging statements confirm successful initialization states and synchronization outcomes.

**Note**: This coroutine must be awaited during the bot's startup sequence before any command handlers are invoked or the event loop begins processing interactions. The execution order is strictly enforced: database stores and the external scraper must complete initialization before command registration to prevent runtime dependency resolution failures. The method relies on the `DISCORD_GUILD_ID` constant to determine synchronization scope; omitting it defaults to global registration, which may take up to one hour to propagate across Discord's servers due to API rate limits. All registered commands are bound to `self.tree`, which must be a valid `discord.app_commands.CommandTree` instance properly attached to the bot client. Developers should ensure that environment variables, database paths, and configuration constants are correctly defined prior to invoking this hook, as missing or misconfigured dependencies will cause initialization failures or silent command registration errors.

## FunctionDef main
**main**: The function of main is to serve as the application entry point that initializes core dependencies, configures logging, validates environment requirements, and launches the Discord bot runtime.
**parameters**: This function does not accept any parameters.
**Code Description**: The `main` function orchestrates the complete startup sequence for the Marvel Rivals tracking Discord bot. It begins by invoking `configure_logging()` to establish a centralized RichHandler-based logging configuration that formats console output and routes messages from both the application root logger and discord.py internal loggers. Following initialization, it performs a critical environment validation by checking for the presence of the `DISCORD_TOKEN` variable; if absent, it terminates execution with a descriptive system exit message directing the user to populate their `.env` file. Upon successful validation, the function instantiates three foundational service layers: `TrackerScraper` for asynchronous web scraping and TTL-based caching of Marvel Rivals player statistics, `RegistrationStore` for managing SQLite-backed Discord-to-Tracker.gg username mappings, and `FeelsStore` for persisting user match rating records. These instances are passed via dependency injection into the `MarvelLoggerBot` constructor, which binds them to the bot's internal command tree, background services, and slash command handlers. Finally, the function triggers the bot's execution loop using `bot.run()`, explicitly passing `log_handler=None` to prevent discord.py from installing its default StreamHandler, thereby preserving the custom logging configuration applied at startup. This design ensures that all external data sources, database interactions, and command synchronization logic are fully wired before the asyncio event loop begins processing Discord API events.
**Note**: The function relies entirely on environment variables, specifically `DISCORD_TOKEN`, which must be populated in a `.env` file prior to execution; failure to provide it will immediately halt the application. The explicit `log_handler=None` argument is mandatory to avoid duplicate or conflicting log outputs, as discord.py would otherwise override the RichHandler configuration established by `configure_logging()`. All instantiated dependencies are created without custom parameters in this entry point, meaning they will rely on their default configurations (such as `DATABASE_PATH` for SQLite files and default scraping timeouts). The function does not handle graceful shutdown logic itself; that responsibility is delegated to the `MarvelLoggerBot.close()` method, which ensures the scraper browser session and database connections are properly terminated when the bot disconnects.
