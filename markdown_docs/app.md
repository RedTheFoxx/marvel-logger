## ClassDef MarvelLoggerBot
**MarvelLoggerBot**: The function of MarvelLoggerBot is to serve as the core Discord bot client that manages game data tracking, user registration, and match rating features while orchestrating command synchronization and lifecycle events.
**attributes**: 
· tracker: An instance of TrackerScraper responsible for asynchronous web scraping and caching of player statistics.
· registrations: An instance of RegistrationStore managing SQLite-backed mappings between Discord accounts and game profiles.
· feels: An instance of FeelsStore persisting user-submitted match rating records.
· tree: An app_commands.CommandTree instance used to register and manage slash commands.
**Code Description**: The MarvelLoggerBot class extends discord.Client and acts as the central runtime controller for the application. During initialization, it configures default Discord intents, instantiates a command tree, and accepts three dependency-injected services: the tracker scraper, registration store, and feels store. Upon startup, the setup_hook method automatically initializes the injected stores and tracker service, then registers six distinct slash commands by invoking external registration functions. It handles command synchronization logic by checking for the DISCORD_GUILD_ID environment variable; if present, it restricts command availability to a specific guild, otherwise it registers them globally across all servers where the bot is invited. The on_ready method triggers when the client establishes a connection to Discord, logging the bot's username and user ID using Rich-formatted output. Finally, the close method ensures graceful termination by closing the background tracker service before calling the parent client's close routine. This class functions in direct coordination with the application entry point, which instantiates its core dependencies and passes them via constructor injection before initiating the asynchronous event loop.
**Note**: The class requires the DISCORD_TOKEN environment variable to be populated by the caller before execution. Command registration behavior is strictly determined by the presence of the DISCORD_GUILD_ID variable, which dictates whether commands sync globally or to a specific guild. The bot relies on external command registration functions that must be available in the execution scope. Rich-formatted logging output depends on the centralized logging configuration established during application startup. All injected dependencies operate with their default configurations unless explicitly overridden elsewhere in the project.

### FunctionDef setup_hook(self)
**setup_hook**: The function of setup_hook is to orchestrate the complete startup sequence of the Discord bot by initializing backend subsystems, registering all slash commands, and synchronizing them with the Discord API.
**parameters**: The parameters of this Function.
· self: The instance of the MarvelLoggerBot class that holds references to the command tree, database stores, scraper client, and configuration variables.
**Code Description**: This asynchronous method serves as the central initialization coordinator for the application lifecycle. It executes a strict sequential startup routine: first, it asynchronously initializes the SQLite persistence layers for user registrations via `self.registrations.init()` and for match rating feedback via `self.feels.init()`, ensuring database schemas are created and connections are ready before any command handlers execute. Next, it activates the external web scraping session via `self.tracker.start()`, preparing the client to fetch and cache data from Tracker.gg with proper rate limiting and browser simulation settings. Following subsystem preparation, the method registers all application slash commands by invoking dedicated factory functions (`register_demo_command`, `register_stats_command`, `register_register_command`, `register_unregister_command`, `register_match_command`, and `register_feels_command`). Each registration function receives the shared `self.tree` instance along with necessary dependency injections (e.g., `self.tracker`, `self.registrations`, `self.feels`) to enable cross-module communication without circular imports. After command registration, the method determines the deployment scope based on the `DISCORD_GUILD_ID` configuration variable. If a guild ID is provided, it copies global commands to the specified Discord guild and synchronizes them locally; otherwise, it performs a global synchronization across all servers where the bot is present. Upon completion, it logs a confirmation message indicating the synchronization target. This method guarantees that all dependencies are fully operational and command definitions are pushed to Discord before the bot begins processing user interactions.
**Note**: The method must be awaited during the bot's initialization phase, typically within the `discord.Client` or `commands.Bot` startup flow. It assumes that all referenced attributes (`self.tree`, `self.registrations`, `self.feels`, `self.tracker`) are correctly instantiated in the class constructor prior to invocation. The synchronization step interacts directly with Discord's REST API and may experience transient delays; developers should account for this latency during deployment. If `DISCORD_GUILD_ID` is omitted or empty, commands will register globally, which can take up to one hour to propagate across all servers. Ensure that the underlying database directories have write permissions and that the Tracker.gg scraping configuration constants are properly set before calling this hook. Any unhandled exceptions during database initialization or scraper startup will propagate through this coroutine, so external error handling at the bot entry point is recommended.

## FunctionDef main
**main**: The function of main is to serve as the application entry point that initializes core dependencies, configures logging, validates environment requirements, and launches the Discord bot runtime.
**parameters**: This function does not accept any parameters.
**Code Description**: The `main` function orchestrates the complete startup sequence for the Marvel Rivals tracking Discord bot. It begins by invoking `configure_logging()` to establish a centralized RichHandler-based logging configuration that formats console output and routes messages from both the application root logger and discord.py internal loggers. Following initialization, it performs a critical environment validation by checking for the presence of the `DISCORD_TOKEN` variable; if absent, it terminates execution with a descriptive system exit message directing the user to populate their `.env` file. Upon successful validation, the function instantiates three foundational service layers: `TrackerScraper` for asynchronous web scraping and TTL-based caching of Marvel Rivals player statistics, `RegistrationStore` for managing SQLite-backed Discord-to-Tracker.gg username mappings, and `FeelsStore` for persisting user match rating records. These instances are passed via dependency injection into the `MarvelLoggerBot` constructor, which binds them to the bot's internal command tree, background services, and slash command handlers. Finally, the function triggers the bot's execution loop using `bot.run()`, explicitly passing `log_handler=None` to prevent discord.py from installing its default StreamHandler, thereby preserving the custom logging configuration applied at startup. This design ensures that all external data sources, database interactions, and command synchronization logic are fully wired before the asyncio event loop begins processing Discord API events.
**Note**: The function relies entirely on environment variables, specifically `DISCORD_TOKEN`, which must be populated in a `.env` file prior to execution; failure to provide it will immediately halt the application. The explicit `log_handler=None` argument is mandatory to avoid duplicate or conflicting log outputs, as discord.py would otherwise override the RichHandler configuration established by `configure_logging()`. All instantiated dependencies are created without custom parameters in this entry point, meaning they will rely on their default configurations (such as `DATABASE_PATH` for SQLite files and default scraping timeouts). The function does not handle graceful shutdown logic itself; that responsibility is delegated to the `MarvelLoggerBot.close()` method, which ensures the scraper browser session and database connections are properly terminated when the bot disconnects.
