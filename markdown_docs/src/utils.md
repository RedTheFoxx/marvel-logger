## FunctionDef validate_tracker_username(username)
**validate_tracker_username**: The function of validate_tracker_username is to verify whether a provided tracker username meets the system's formatting and length requirements, returning an error message if invalid or None if valid.
**parameters**: The parameters of this Function.
· username: A string representing the tracker username to be validated.
**Code Description**: This function serves as a centralized validation gate for usernames intended for external gaming tracker services. It executes two sequential checks on the input string. First, it evaluates whether the string is empty or falsy. If so, it returns a hardcoded French error message indicating that the username cannot be blank. Second, it applies a precompiled regular expression pattern (`TRACKER_USERNAME_PATTERN`) to verify that the username contains only permitted characters (letters, digits, hyphens, underscores, and periods) and adheres to a maximum length of 32 characters. If the string fails this pattern match, it returns a descriptive French error message detailing the allowed character set and length constraint. If both checks pass successfully, the function returns `None`, signaling that the input is valid for downstream processing. Within the project architecture, this utility is consistently invoked by command handlers in the registration, statistics, and match resolution modules. Each caller strips leading and trailing whitespace from the raw user input before passing it to this function. Upon receiving a truthy return value (the error message string), the callers immediately halt execution and present an ephemeral Discord embed containing the validation failure to the user. When `None` is returned, processing continues with profile fetching or database registration operations. This design centralizes username formatting rules, prevents unnecessary network requests for malformed inputs, and ensures consistent input sanitization across all tracker-related commands.
**Note**: The function relies on a module-level constant named `TRACKER_USERNAME_PATTERN`, which must be defined elsewhere in the codebase as a compiled regular expression object. The error messages are hardcoded in French; ensure your application's localization strategy aligns with this or consider making them configurable if multilingual support is required. The validation strictly enforces a maximum length of 32 characters and a specific character whitelist, so usernames containing spaces, special symbols, or exceeding the limit will be rejected before any external API calls are initiated.
**Output Example**: 
- Valid input: `validate_tracker_username("Player_One-123")` returns `None`
- Invalid input (empty): `validate_tracker_username("")` returns `"Le pseudo ne peut pas être vide."`
- Invalid input (bad format): `validate_tracker_username("Invalid@Name!")` returns `"Pseudo invalide. Utilisez uniquement lettres, chiffres, tirets, underscores ou points (max 32 caractères)."`
