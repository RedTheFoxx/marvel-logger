## ClassDef RegistrationStore
**RegistrationStore**: The function of RegistrationStore is to manage the persistent storage, retrieval, and lifecycle of Discord user ID to Tracker.gg username mappings using a SQLite database.

**attributes**: The attributes of this Class.
· _path: str | None = None (Constructor parameter specifying the SQLite database file path; defaults to DATABASE_PATH if omitted)

**Code Description**: RegistrationStore provides an asynchronous interface for CRUD operations on user registration data. It internally offloads synchronous SQLite interactions to a thread pool via asyncio.to_thread to prevent blocking the main event loop. The class handles database initialization, which creates necessary parent directories and executes a predefined schema (_SCHEMA). Core methods include count_for_user for quota enforcement, list_for_user for retrieving registered usernames ordered by registration time, has_user_pseudo for case-insensitive duplicate checking, add for inserting new mappings with normalized lowercase usernames and UTC timestamps, and remove for deleting specific mappings. The class is instantiated during bot startup in main() and injected into the MarvelLoggerBot instance. It is functionally utilized across multiple Discord slash commands: /register uses it to validate quotas, check for existing links, and persist new registrations; /unregister relies on it to verify existence before deletion and update remaining lists; /match and /feels commands use list_for_user to resolve default usernames when none are explicitly provided by the user. All database connections are properly managed with try...finally blocks to ensure cleanup.

**Note**: The class expects the SQLite database file path to be writable, as it automatically creates parent directories during initialization. Username normalization is strictly enforced via lowercase conversion before storage and querying, meaning case variations of the same username are treated as identical. The async methods must be awaited, and synchronous internal methods should not be called directly in production code. Database schema changes require updates to _SCHEMA outside this class.
