## FunctionDef register_register_command(tree, tracker, store)
**register_register_command**: The function of register_register_command is to define and register the Discord slash command `/register` that links a Discord account to one or more Tracker.gg usernames, enforcing validation rules and quota limits.

**parameters**: The parameters of this Function.
· tree: app_commands.CommandTree - The command tree instance used to attach the newly defined slash command to the bot's routing system.
· tracker: TrackerScraper - An asynchronous scraper instance responsible for fetching, caching, and validating player profile data from Tracker.gg.
· store: RegistrationStore - An asynchronous SQLite persistence layer that manages Discord user ID to Tracker.gg username mappings, including quota enforcement and duplicate checking.

**Code Description**: This function operates as a command factory that dynamically creates the `/register` slash command and binds it to the provided `CommandTree`. When invoked by a user, the inner coroutine executes a sequential validation pipeline: it trims whitespace from the input, runs a format validation check, verifies case-insensitive uniqueness via `store.has_user_pseudo`, and enforces the per-user registration limit using `store.count_for_user` against `MAX_REGISTRATIONS_PER_USER`. Upon passing these checks, the command defers its ephemeral response to prevent Discord API timeouts while asynchronously retrieving the player profile through `tracker.fetch_profile`. If successful, the mapping is persisted via `store.add`, and the updated list of linked usernames is fetched via `store.list_for_user` to populate a success embed. The function implements granular exception handling for `ProfileNotFoundError`, `TrackerRateLimitError`, `TrackerScraperError`, and generic exceptions, logging execution duration and sending appropriate ephemeral error embeds. It is invoked during bot initialization within `MarvelLoggerBot.setup_hook` in `app.py`, where it receives the shared command tree, scraper, and database store instances to ensure centralized dependency injection and command synchronization across the application lifecycle.

**Note**: The function relies on external configuration constants such as `MAX_REGISTRATIONS_PER_USER` and assumes that `TrackerScraper` has been properly initialized via its `start()` method before execution. Username normalization is strictly enforced through lowercase conversion, meaning case variations of the same IGN are treated as identical across all database queries. All user-facing responses are ephemeral, restricting visibility to the invoking Discord user only. The command must be executed within an active asynchronous event loop, and any changes to Tracker.gg's API structure or the underlying SQLite schema will require corresponding updates to the validation logic, exception handling paths, or persistence methods.

**Output Example**: Since this function registers a Discord slash command rather than returning a direct value, its operational output is the successful attachment of the `/register` command to the bot's tree and the subsequent ephemeral embeds sent upon execution. A typical successful interaction would display an embed containing the linked Tracker.gg profile details and the updated list of usernames (e.g., `["PlayerOne", "PlayerTwo"]`) for that Discord account, accompanied by a console log entry: `[green]/register OK[/] PlayerOne lié pour UserDisplay (1/3) — 2.4s`. Error interactions would similarly return ephemeral embeds detailing validation failures, quota limits, or scraper-specific exceptions like rate limits or missing profiles.
### FunctionDef register(interaction, username)
**register**: The function of register is to handle the `/register` slash command by validating a requested Tracker.gg username, checking database constraints, fetching external profile data, persisting the link, and returning contextual feedback to the user via ephemeral Discord messages.
**parameters**: The parameters of this Function.
· interaction: A discord.Interaction object representing the slash command invocation context, providing access to the invoking user, response methods, and deferred message handling capabilities.
· username: A string containing the raw Tracker.gg username provided by the user, which will be stripped of leading and trailing whitespace before validation and processing.
**Code Description**: This async function serves as the primary command handler for linking external gaming profiles to Discord accounts within the registration feature. It orchestrates a multi-stage workflow that begins with input sanitization and validation via `validate_tracker_username`, ensuring the provided string conforms to system formatting rules. Upon successful validation, it queries the persistent storage layer through `store.has_user_pseudo` to prevent duplicate bindings for the same Discord user ID. If no duplicate exists, it evaluates the per-user registration limit using `store.count_for_user`, comparing the current count against the configured maximum threshold. When all preconditions pass, the function defers the interaction response to avoid Discord API timeouts during external network operations. It then invokes `tracker.fetch_profile` to retrieve and parse the target player's data from Tracker.gg. On success, the link is persisted via `store.add`, the updated list of linked usernames is retrieved through `store.list_for_user`, and a confirmation embed is dispatched using `build_register_success_embed`. The function implements comprehensive exception handling: it catches `ProfileNotFoundError` for missing external accounts, `TrackerRateLimitError` for API cooldowns, `TrackerScraperError` for scraping failures, and a generic `Exception` fallback. Each error path logs diagnostic information at appropriate severity levels and returns a standardized error embed via `build_error_embed`. Throughout execution, ephemeral messaging is enforced to ensure only the command invoker receives feedback.
**Note**: Points to note about the use of the code
· The function must be executed within an asynchronous event loop context due to its reliance on `await` for database queries and external API calls.
· All user-facing responses are delivered as ephemeral messages, meaning they are only visible to the requesting Discord user and will not appear in public channels.
· The interaction defer step is critical; omitting it before calling `tracker.fetch_profile` may trigger Discord's 3-second response timeout error.
· Database operations are offloaded to background threads via `asyncio.to_thread` internally, so this handler remains non-blocking for the main event loop.
· Error messages and embed text are hardcoded in French; localization should be addressed if multilingual support is required.
· The function assumes `MAX_REGISTRATIONS_PER_USER` and other configuration constants are accessible in the module scope.
**Output Example**: Since this function returns `None`, observable outcomes depend on execution paths:
- Success path: An ephemeral Discord embed titled "Pseudo enregistré" appears, displaying the newly linked username, current quota usage (e.g., 1/5), and a direct link to the Tracker.gg profile.
- Validation failure: An ephemeral red-bordered embed titled "Erreur" displays a message such as "Pseudo invalide. Utilisez uniquement lettres, chiffres, tirets, underscores ou points (max 32 caractères)."
- Quota exceeded: An ephemeral red-bordered embed titled "Limite atteinte" indicates the maximum registration limit has been reached and lists existing linked usernames.
- Profile not found: An ephemeral error embed displays a message confirming the external account could not be located on Tracker.gg.
All paths conclude with `None` return to the Discord interaction framework.
