## FunctionDef _outcome_label(outcome)
**_outcome_label**: The function of _outcome_label is to translate a raw match outcome string into a localized French display label for user-facing interfaces.

**parameters**: The parameters of this Function.
· outcome: A string representing the result of a match, typically expected to be "win" or any other value indicating a loss.

**Code Description**: This function accepts a single string parameter `outcome` and returns a corresponding French label based on a direct conditional check. If the input exactly matches the lowercase string "win", it returns "Victoire"; for any other input, it defaults to returning "Défaite". As an internal utility function (indicated by the leading underscore), it is not intended for direct external use but serves as a centralized mapping layer for match result terminology. Within the project's embed generation pipeline, this function is invoked by three distinct callers to maintain consistent visual representation of match outcomes. The `_entry_line` function utilizes the output to append the match status to a formatted list line alongside score, map, and hero statistics. Both `build_feels_rating_prompt_embed` and `build_feels_saved_embed` incorporate the result into Discord embed descriptions to clearly communicate whether the rated or confirmed match was a victory or defeat before presenting rating prompts or confirmation summaries. By centralizing this logic, the codebase ensures that any future terminology updates or localization changes only require modification in this single location rather than across multiple embed builders.

**Note**: The function performs an exact string comparison against "win". It does not handle case-insensitivity, partial matches, or alternative loss indicators (e.g., "loss", "defeat", or empty strings), all of which will correctly resolve to "Défaite". Developers consuming upstream data must ensure that match result fields are normalized to lowercase "win" before passing them to this function to avoid unintended default labeling. Additionally, because the output is hardcoded in French, this function should only be used in contexts where the application language or user locale is explicitly set to French.

**Output Example**: 
Input: `outcome = "win"` -> Output: `"Victoire"`
Input: `outcome = "loss"` -> Output: `"Défaite"`

· entry: MatchListEntry - A data model instance containing structured match metadata, including outcome, score, map name, hero information, and KDA ratio.
· rated: bool - A boolean flag indicating whether the user has already provided a rating for this specific match.
**Code Description**: This function generates a formatted string representation of a single match entry intended for inclusion in a Discord embed field. It begins by evaluating the `rated` parameter to assign a localized status indicator: "✅ noté" for rated matches and "⬜ à noter" for unrated ones. The caller passes a 1-based enumeration of `MatchBundle.entries` along with a boolean check against a set of already-rated match IDs. This design centralizes list item formatting logic, ensuring consistent visual presentation across the match rating overview while keeping data extraction and string construction decoupled from embed generation.
**Note**: The function assumes that all attributes accessed on the `entry` object (`outcome`, `score`, `map_name`, `hero.name`, `kda_ratio`) are properly initialized and non-null, as no defensive checks are implemented. The output language is hardcoded to French, making it suitable only for contexts where the application locale is explicitly set to French. The `_outcome_label` dependency expects normalized lowercase input ("win" or other values), so upstream data must be preprocessed accordingly.
