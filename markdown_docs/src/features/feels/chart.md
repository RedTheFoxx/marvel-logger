## FunctionDef _configure_chart_style
**_configure_chart_style**: The function of _configure_chart_style is to configure global matplotlib font settings for consistent cross-platform chart rendering.
**parameters**: This function does not accept any parameters.
**Code Description**: This function updates the global runtime configuration dictionary of the matplotlib library by modifying plt.rcParams. It explicitly sets the default font family to sans-serif and defines a prioritized fallback list consisting of Segoe UI, Inter, Helvetica Neue, DejaVu Sans, and a generic sans-serif typeface. By applying these configurations before any figure creation, it ensures that all textual elements in generated plots maintain uniform typography across different operating systems. In the project architecture, this function is invoked at the initialization phase of render_feels_chart. Its execution establishes the necessary typographic baseline before the bar chart figure and axes are instantiated, guaranteeing that match ratings, axis labels, annotations, and legend text render consistently throughout the visualization pipeline.
**Note**: This function modifies global matplotlib state, so it should be invoked only once per application lifecycle or immediately prior to the first chart generation. Subsequent calls may overwrite existing configuration settings. Ensure that the matplotlib module is imported with the alias plt before execution, as the function directly references plt.rcParams.
## FunctionDef _bar_color(outcome)
**_bar_color**: The function of _bar_color is to map a match outcome string to a specific color constant for chart visualization.
**parameters**: The parameters of this Function.
· outcome: A string or None value representing the result of a match, expected to be "win", "loss", or any other value (including None).
**Code Description**: This function acts as a deterministic color mapper for data visualization purposes. It evaluates the `outcome` parameter and returns a predefined color constant corresponding to the match result. If the outcome is exactly "win", it returns `_WIN`. If the outcome is exactly "loss", it returns `_LOSS`. For any other input, including None or unrecognized strings, it defaults to returning `_NEUTRAL`. Within the project architecture, this function is utilized by `render_feels_chart` to dynamically assign colors to individual bars in a matplotlib bar chart. The caller iterates over a list of match records and passes each record's `outcome` attribute to `_bar_color`, generating a sequence of color strings that are directly applied to the chart bars via the `color` parameter. This design isolates the color-assignment logic from the plotting routine, ensuring that visual elements accurately reflect the underlying match results (victory, defeat, or neutral/unknown) while maintaining clean separation of concerns and reducing conditional complexity in the main rendering function.
**Note**: The function relies on external constants `_WIN`, `_LOSS`, and `_NEUTRAL` which must be defined in the same module or imported beforehand. It performs exact string matching, so case sensitivity matters (e.g., "Win" will not match "win"). The return type is strictly a string, typically expected to be a valid matplotlib color specification such as a hex code or named color. Ensure that the `outcome` values passed from the caller align with the expected strings to avoid unintended default coloring.
**Output Example**: 
Input: outcome = "win" -> Output: <value of _WIN constant>
Input: outcome = "loss" -> Output: <value of _LOSS constant>
Input: outcome = None -> Output: <value of _NEUTRAL constant>
## FunctionDef _bar_label(record)
**_bar_label**: The function of _bar_label is to generate a concise, multi-line string label for a specific match record, optimized for display on a chart's x-axis.
**parameters**: The parameters of this Function.
· record: MatchFeelsRecord - A structured data object containing match details such as hero name, play timestamp, and match identifier.
**Code Description**: This function constructs a display label by evaluating available attributes within the provided MatchFeelsRecord instance. It prioritizes readability by first checking for a hero_name; if present, it is added to the label components. Next, it checks for a played_at timestamp; if available, it formats the date as day and month (%d/%m) and appends it. If neither attribute contains data, the function falls back to using the first eight characters of the match_id to ensure every bar receives a unique identifier. Finally, all collected components are joined with newline characters to create a compact vertical layout suitable for chart axis labels. Within the project, this function is invoked by render_feels_chart during the generation of a bar chart visualizing subjective match ratings. It processes each record in the input list via a list comprehension and passes the resulting strings to ax.set_xticklabels, enabling users to quickly identify matches by hero, date, or ID directly on the visualization.
**Note**: The function relies on null-safe evaluation of optional attributes (hero_name and played_at) to prevent attribute access errors. Since chart axis labels have limited horizontal space, the newline join ensures vertical stacking without truncation. Developers should ensure that MatchFeelsRecord instances passed to this function are properly initialized, as missing or malformed data will trigger the fallback to match_id. The date formatting assumes the played_at attribute is a valid datetime object; passing incompatible types will raise an AttributeError during strftime execution.
**Output Example**: 
D.Va
15/08

Or (fallback case):
abc12345
## FunctionDef render_feels_chart(records)
**render_feels_chart**: The function of render_feels_chart is to generate a dynamic PNG bar chart visualizing subjective match ratings alongside their average, returning the image data as bytes.
**parameters**: The parameters of this Function.
· records: list[MatchFeelsRecord] - A sequence of structured match evaluation records containing rating scores, match outcomes, and contextual metadata required for chart generation.
**Code Description**: The function processes a list of MatchFeelsRecord instances to produce a matplotlib-generated bar chart. It begins by validating that the input list is not empty, then applies global font configuration via _configure_chart_style to ensure cross-platform typographic consistency. The function extracts rating values and computes their arithmetic mean, while dynamically determining the figure width based on the number of records to prevent label overlap. A matplotlib figure and axes are instantiated with specific dimensions, DPI, and background colors. Bars are plotted using a color mapping function (_bar_color) that assigns distinct colors based on each record's match outcome (win, loss, or neutral). Each bar is annotated with its numerical rating value. A dashed horizontal line represents the calculated average rating, accompanied by a labeled annotation positioned at the top-left of the plot area. The x-axis labels are generated via _bar_label, which prioritizes hero names and play dates, falling back to truncated match IDs when necessary. Axis limits, tick locators, grid lines, spines, and the y-axis label are configured for readability. A text block indicating the total number of rated matches is placed in the top-left corner, and a legend clarifies the color coding for outcomes and the average line. Finally, the figure is rendered to a BytesIO buffer as a PNG image, closed, and returned as raw bytes. Within the project architecture, this function is invoked asynchronously via asyncio.to_thread by both the /feels slash command handler in register_feels_command/feels and the FeelsRatingView._on_rating_select callback in view.py. The returned byte stream is immediately wrapped in a discord.File object to be attached to Discord embed responses, ensuring non-blocking execution of the CPU-intensive plotting routine while maintaining event loop responsiveness.
**Note**: The function raises a ValueError if an empty list is passed; callers must ensure records are available before invocation. It modifies global matplotlib state (plt.rcParams) via _configure_chart_style, so it should ideally be called once per application lifecycle, though repeated calls in this context are safe as they overwrite with identical values. The dynamic width calculation uses a clamp between 7.0 and 12.0 inches to maintain reasonable chart proportions regardless of record count. All matplotlib figures are explicitly closed with plt.close(fig) after saving to prevent memory leaks in long-running applications. The function relies on external constants (_BG, _PANEL, _AVG_LINE, etc.) and helper functions (_bar_color, _bar_label) defined in the same module; these must remain accessible during execution.
**Output Example**: Returns a bytes object containing a valid PNG image stream. When decoded, it produces a horizontal bar chart with a 10-point scale y-axis, colored bars corresponding to match outcomes, an annotated average line, and x-axis labels formatted as "HeroName\nDD/MM" or truncated IDs. The exact byte length varies based on the number of records and DPI settings, typically ranging from 20KB to 80KB for standard inputs.
