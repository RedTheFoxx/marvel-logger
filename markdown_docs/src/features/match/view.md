## ClassDef MatchPickerView
**MatchPickerView**: The function of MatchPickerView is to provide an interactive Discord UI component that allows users to select a specific match from a provided bundle and view its corresponding details or availability status.

**attributes**: 
· _bundle: Stores the MatchBundle object containing the list of match entries and optional detailed match data.
· _entries_by_id: A dictionary mapping each match ID to its corresponding entry object, enabling O(1) lookup during selection.
· timeout: Inherited from discord.ui.View, initialized to _SELECT_TIMEOUT to define the active lifespan of the interactive component before it automatically expires.

**Code Description**: 
MatchPickerView extends discord.ui.View and is responsible for rendering a dropdown selection interface for match records. During initialization, it processes a MatchBundle object to construct a list of discord.SelectOption objects. Each option is formatted with a label containing the match index, outcome (V for win, D for draw), score, and map name, along with a description displaying the hero name, KDA ratio, and game mode. Both label and description strings are truncated to 100 characters to comply with Discord API constraints. The view initializes a single-select dropdown component that triggers the _on_select callback upon user interaction. When a match is selected, the callback extracts the match ID from the interaction data and performs lookups in self._entries_by_id and self._bundle.details. If detailed data exists, it generates a match detail embed; otherwise, it generates an unavailable match embed. The original message is then updated to display the embed, and the interactive view is removed by passing view=None to prevent redundant interactions. If no matching data is found, an ephemeral error message is sent. The class implements an on_timeout method that disables all interactive components in the view and attempts to update the associated Discord message to reflect the disabled state, silently handling discord.HTTPException if the message has already been deleted or modified. Functionally, this component is tightly coupled with the /match command in src/features/match/command.py. The command fetches a MatchBundle from the tracker, instantiates MatchPickerView with that bundle, and delivers it as a followup message. This integration enables users to interactively browse their match history directly within the Discord interface, transitioning from a static list to an actionable selection mechanism that dynamically updates the message content based on user input.

**Note**: 
The view depends on external configuration constants such as _SELECT_TIMEOUT for its operational window. All string formatting strictly enforces Discord API length limits to prevent payload rejection errors. The component operates statelessly regarding the bundle after initialization, relying entirely on precomputed internal dictionaries for data retrieval. Users must interact within the defined timeout period; otherwise, the dropdown becomes permanently disabled. The view automatically removes itself after a successful selection to maintain message cleanliness and prevent duplicate processing. Error handling is localized to ephemeral responses or silent HTTP exception suppression during timeout cleanup.

**Output Example**: 
A Discord followup message displaying an embed titled "Match Selector" with a dropdown menu labeled "Choisir un match…". Upon selecting an option (e.g., "#1 V 25 · de_dust2"), the message updates to display a detailed embed containing hero statistics, KDA ratio, and game mode information, while the dropdown is removed. If the timeout expires without interaction, the dropdown remains visible but becomes unclickable with a disabled state, and no further selections are processed until a new command invocation occurs.

The provided MatchBundle is stored as an instance attribute, and a reverse lookup dictionary (_entries_by_id) is generated to map each match ID to its corresponding entry object for O(1) retrieval during selection events. The method then iterates through bundle.entries to dynamically generate Discord SelectOption objects. Finally, the configured select component is attached to the view via add_item, completing the UI setup. This initialization directly bridges the raw MatchBundle data structure with Discord.py's interactive components, preparing the view for deployment in a channel or interaction context.

### FunctionDef _on_select(self, interaction)
**_on_select**: The function of _on_select is to process a user's selection from a Discord interactive picker menu, retrieve the corresponding match data, generate an appropriate embed response, and update the interaction message accordingly.

**parameters**: The parameters of this Function.
· interaction: discord.Interaction - Represents the Discord interaction event triggered when a user selects an option from the picker view. Contains payload data including the selected match ID and user context.

**Code Description**: This asynchronous method serves as the callback handler for the match selection interface within the MatchPickerView class. Upon invocation, it extracts the chosen match identifier from the interaction payload and queries two internal data structures: _entries_by_id (a dictionary mapping match IDs to basic match list entries) and _bundle.details (a dictionary containing comprehensive match detail objects). The method implements a priority-based fallback mechanism for data retrieval. If detailed match statistics are available in _bundle.details, it delegates to build_match_detail_embed to generate a rich, formatted Discord embed displaying scores, rosters, and performance metrics. If detailed data is absent but a basic entry exists, it invokes build_match_detail_unavailable_embed to produce a fallback embed with an external tracker link. When neither data source contains the selected match ID, it responds with an ephemeral "Match introuvable." message and terminates execution. Upon successful embed generation, the method updates the original interaction message by replacing its content with the new embed and stripping away the interactive view components via view=None. Finally, it logs a structured informational message recording the selection event, including the match ID, the tracked player's username, and the interacting user's display name. The function is directly wired as the callback for the discord.ui.Select component initialized in MatchPickerView.__init__, acting as the central routing logic between user input and data presentation layers.

**Note**: Developers should ensure that _bundle.details and _entries_by_id are properly populated before the picker view is displayed, as missing keys will trigger fallback or error paths. The method assumes interaction.data["values"][0] always contains a valid string match ID; type ignore comments indicate reliance on Discord.py's runtime payload structure. Since the method calls interaction.response.edit_message, it must be invoked within a valid interaction context where the response has not yet been deferred or followed up with a message that would block editing. The removal of the view (view=None) is permanent for that message, so any subsequent interactions require re-sending the message with a new view instance. Logging relies on the configured logger instance; ensure it is properly initialized in the application context to avoid runtime errors during selection events.

**Output Example**: The method does not return a value. Upon successful execution with available detail data, the original interaction message is updated to display a formatted Discord embed containing match statistics, team rosters, and player performance metrics, with all interactive buttons removed. If only basic entry data exists, the message displays an orange fallback embed prompting the user to view details on Tracker.gg. In the absence of both data sources, an ephemeral system message "Match introuvable." is sent exclusively to the requesting user.

### FunctionDef on_timeout(self)
**on_timeout**: The function of on_timeout is to disable all interactive components within the view and update the associated Discord message when the view's timeout period expires.
**parameters**: The parameters of this Function.
· self: The instance of the MatchPickerView class that invokes this method.
**Code Description**: The description of this Function.
This asynchronous method operates as a callback handler automatically triggered by the Discord.py framework when the configured timeout duration for the view elapses without user interaction. Upon execution, it iterates through every child component attached to the view and sets their disabled attribute to True, effectively preventing further clicks or selections. The method subsequently checks if the self.message attribute holds a valid reference to a Discord message. If a message exists, it asynchronously updates that original message by passing the modified view object to the edit method. This synchronization ensures that the visual state of the interface on Discord accurately reflects the newly disabled status of its components. The update operation is enclosed in a try-except block that specifically catches discord.HTTPException. This exception handling manages potential failures such as message deletion, permission restrictions, or network interruptions, allowing the application to continue execution without raising unhandled errors.
**Note**: Points to note about the use of the code
This method relies entirely on the internal timeout mechanism of the Discord.py view system and does not require manual invocation by external code. Developers should ensure that the self.message attribute is correctly initialized before the timeout event occurs to guarantee successful interface updates. The silent exception handling intentionally suppresses HTTP errors, which prevents application crashes but may obscure debugging information if message synchronization fails unexpectedly. Additionally, because the method modifies component states asynchronously, any subsequent logic depending on these disabled states must account for Discord's asynchronous update propagation time.
