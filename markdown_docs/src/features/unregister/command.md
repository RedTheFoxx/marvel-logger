## FunctionDef register_unregister_command(tree, store, feels)
**register_unregister_command**: The function of register_unregister_command is to define and register a Discord slash command that dissociates a Tracker.gg username from a Discord account while cleaning up associated match rating data.

**parameters**: The parameters of this Function.
· tree: An instance of discord.app_commands.CommandTree used to bind the newly defined slash command to the bot's command hierarchy.
· store: An instance of RegistrationStore responsible for managing and querying persistent Discord-to-Tracker.gg username registration mappings in a SQLite database.
· feels: An instance of FeelsStore responsible for managing and deleting persistent match rating records linked to specific usernames.

**Code Description**: This function defines an asynchronous slash command named `/unregister` within the provided command tree. Upon invocation, it extracts the requesting Discord user's display name and ID, strips whitespace from the input username, and normalizes it to lowercase for case-insensitive database queries. It first verifies whether the specified normalized username is currently linked to the requester's Discord account using `store.has_user_pseudo`. If the link does not exist, it responds with an ephemeral embed indicating the user is not registered. If the link exists, it proceeds to delete all associated match rating records by calling `feels.delete_for_username`, which returns the count of deleted rows. Subsequently, it removes the registration mapping from the database via `store.remove`. If the removal fails unexpectedly, it sends an error embed. On success, it fetches the remaining registered usernames for the account using `store.list_for_user` and sends a success embed containing the username, remaining list, and the count of deleted feels records. The function logs execution details, including duration and operation status, and catches any unexpected exceptions to log them and notify the user. Functionally, it acts as the central orchestration layer for account dissociation, bridging the `RegistrationStore` and `FeelsStore` data access layers. It is invoked during bot startup by `MarvelLoggerBot.setup_hook` in `app.py`, which injects the initialized store instances into this function to bind the command to the Discord application tree before global or guild synchronization.

**Note**: The input username must be provided as a string; whitespace is automatically stripped and case is normalized to lowercase internally, meaning case variations of the same name are treated identically. The `store.remove` method returns a boolean indicating whether a row was actually deleted, which should be handled carefully as it may return False if concurrent modifications occur. All database operations rely on asynchronous delegation to background threads via asyncio.to_thread, so this function must be awaited in an async context. Ephemeral responses are used throughout, meaning only the command invoker can view the feedback messages. The helper embed builders (build_not_registered_embed, build_unregister_error_embed, build_unregister_success_embed) are external dependencies and must be available in scope.

**Output Example**: 
Upon successful execution, the function sends an ephemeral Discord embed to the user containing:
- Title: Unregister Successful
- Description: Successfully removed « PlayerOne » from your account.
- Field: Remaining registrations -> ["PlayerTwo", "PlayerThree"]
- Field: Deleted feels records -> 15
The function itself returns None as it is a Discord slash command handler.
### FunctionDef unregister(interaction, username)
**unregister**: The function of unregister is to asynchronously process a user's request to dissociate a specific tracker username from their Discord account, handle related data cleanup, and provide contextual feedback through Discord embeds.
**parameters**: The parameters of this Function.
· interaction: A discord.Interaction object representing the slash command execution context, containing user information and response methods.
· username: A string representing the tracker username provided by the user that needs to be unregistered.
**Code Description**: This asynchronous function serves as the core handler for the unregister command within a Discord bot application. Upon invocation, it extracts the requester's display name and Discord user ID from the interaction context, normalizes the input username to lowercase, and logs the operation. The function first validates the existence of the registration by querying the persistence layer via has_user_pseudo. If the record is absent, it immediately responds with a warning embed indicating the username is not linked. Upon successful validation, the function proceeds to execute the unregistration workflow. It calls delete_for_username to purge all associated tracking records tied to the Discord user ID and normalized username, capturing the count of deleted entries. Subsequently, it invokes remove on the registration store to delete the primary linkage record from the database. The function explicitly verifies the boolean return value of remove to ensure the deletion affected exactly one row; failure triggers an internal error embed. After successful removal, it queries list_for_user to retrieve the updated set of remaining linked usernames for the account. Finally, it constructs and dispatches a success embed containing the removed username, the count of purged feels, and the list of remaining pseudonyms, followed by a performance log entry. The entire operation is wrapped in a try-except block to catch unexpected runtime exceptions, ensuring that any unhandled errors are logged with timing details and communicated to the user via a generic error embed.
**Note**: Points to note about the use of the code
· This function must be executed within an asynchronous event loop context using await.
· The username parameter is automatically stripped of leading/trailing whitespace and normalized to lowercase before database queries, ensuring case-insensitive matching consistency.
· All user-facing responses are sent as ephemeral messages, meaning they are only visible to the command requester and do not clutter public channels.
· The function relies on deterministic boolean returns from remove and integer counts from delete_for_username; callers should not assume these operations succeed without checking their return values or handling exceptions.
· Database connections and thread pool delegations for all underlying store methods are managed internally by the persistence layer, so this command handler does not need to manage connection lifecycles directly.
**Output Example**: Since the function signature specifies a return type of None, it does not produce a direct programmatic return value. Instead, its functional output manifests as Discord API interactions. A successful execution would trigger an ephemeral embed response with the title "Pseudo retiré", a description confirming the dissociation of the specified username, a bulleted list of remaining linked usernames, and a note indicating the number of associated feels deleted. In failure scenarios, it would instead dispatch either a warning embed titled "Pseudo introuvable" or an error embed titled "Erreur", depending on whether the record was missing or an exception occurred during processing.
