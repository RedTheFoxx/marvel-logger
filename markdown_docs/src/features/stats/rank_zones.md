## ClassDef RankZone
**RankZone**: The function of RankZone is to define a structured data model representing a specific rank score tier with its boundaries, display label, unique identifier, and visualization color.
**attributes**: The attributes of this Class.
· key: str - A unique string identifier for the rank zone.
· label: str - The human-readable name displayed for the zone.
· rs_min: int - The inclusive lower bound of the rank score range.
· rs_max: int | None - The exclusive upper bound of the rank score range, or None if the tier extends indefinitely upward.
· color: str - A string representing the color used to render the zone in visualizations.
**Code Description**: RankZone serves as a lightweight data container that encapsulates all necessary metadata for defining and rendering a specific rank score interval within statistical charts. It does not contain behavioral methods but acts as a configuration object passed throughout the stats module. The class is instantiated by _build_major_rank_zones, which maps raw configuration tuples into structured RankZone objects using predefined label and color mappings. Once created, these instances are stored in a global collection (MAJOR_RANK_ZONES) and utilized by lookup functions such as zone_for_rs and zones_intersecting. These functions rely on the rs_min and rs_max attributes to perform range comparisons, determine tier membership for a given rank score, or identify overlapping tiers within a specified RS window. In the charting pipeline (src/features/stats/chart.py), RankZone objects are consumed by multiple rendering helpers. The _zone_top_rs function resolves the effective upper boundary by handling the None case for unbounded tiers. Boundary drawing functions (_draw_zone_boundaries) and span fillers (_draw_zone_span) extract rs_min, rs_max, and color to plot horizontal lines and shaded regions on a matplotlib axis. Label positioning logic (_zone_label_y) calculates vertical coordinates based on the zone's score range, while _draw_zone_label uses the label and color attributes to annotate the chart. The key attribute is primarily used for filtering or highlighting specific tiers via _label_zones_for. Collectively, these interactions demonstrate that RankZone functions as a central schema bridging configuration data, range logic, and visualization rendering.
**Note**: When using this class, ensure that rs_max is explicitly set to None only when the tier has no upper limit, as downstream range-checking logic treats None as positive infinity. The rs_min value is always inclusive, while rs_max is treated as exclusive in membership checks. All visualization functions expect valid color strings and will render incorrectly if these attributes are missing or malformed. The class relies on external configuration sources for initialization and does not validate range consistency internally.
## FunctionDef _major_rank_rs_bounds
**_major_rank_rs_bounds**: The function of _major_rank_rs_bounds is to compute and return a list of tuples defining the inclusive lower and exclusive upper rank score boundaries for each major game rank, with an unbounded upper limit for the final rank.
**parameters**: The parameters of this Function.
· None: This function does not accept any input parameters.
**Code Description**: The function initializes an empty list to store boundary data and iterates through a predefined sequence of major rank keys. During iteration, it skips the special top-tier ranks "eternity" and "one_above_all". For each standard rank, it calculates the minimum rank score by applying an index-based offset to a base value, and derives the maximum rank score by adding a fixed step size to the minimum. Each calculated range is appended as a tuple containing the rank key, the minimum score, and the maximum score. After processing the standard ranks, the function calculates the endpoint of the Celestial I tier and explicitly appends the "eternity" rank with a fixed upper bound derived from a subdivision constant. It then appends the "one_above_all" rank with an unbounded upper limit represented by None. The populated list is returned to the caller. Functionally, this output serves as the foundational data structure for _build_major_rank_zones, which unpacks each tuple to instantiate RankZone objects, thereby mapping rank identifiers to their corresponding score thresholds, labels, and visual attributes for runtime progression checks.
**Note**: The returned boundaries utilize a half-open interval convention where the lower bound is inclusive and the upper bound is exclusive. For the highest tier, the upper bound is explicitly set to None to indicate an infinite cap. All calculations depend on external module constants and configuration sequences; modifying these dependencies without updating their definitions will break rank progression logic. The function assumes _MAJOR_RANK_ORDER contains all standard ranks before the special tiers.
**Output Example**: [("bronze_iii", 0, 100), ("bronze_ii", 100, 200), ("silver_iii", 300, 400), ("gold_iii", 600, 700), ("eternity", 700, 800), ("one_above_all", 800, None)] (Values are illustrative and depend on the actual magnitude of BRONZE_III_RS, _SUBDIVISIONS_PER_MAJOR, and RS_PER_SUBDIVISION)
## FunctionDef _build_major_rank_zones
**_build_major_rank_zones**: The function of _build_major_rank_zones is to construct and return a tuple of RankZone objects that represent the major rank score tiers with their corresponding metadata and boundaries.
**parameters**: None. This function does not accept any input parameters.
**Code Description**: The function operates as a configuration mapper that transforms raw rank score boundaries into structured RankZone instances. It iterates over the sequence of tuples yielded by _major_rank_rs_bounds(), unpacking each tuple into key, rs_min, and rs_max. For every iteration, it retrieves the human-readable display label from the _MAJOR_LABELS dictionary using the rank key, and fetches the corresponding visualization color from the _MAJOR_COLORS dictionary. These values are passed as positional arguments to the RankZone constructor alongside the score boundaries. The resulting RankZone instances are collected via a generator expression and immediately converted into an immutable tuple before being returned. This design ensures that all major rank tiers are precomputed at module load time, providing a consistent and efficient lookup structure for downstream statistical calculations and chart rendering pipelines. The function relies entirely on external configuration mappings (_MAJOR_LABELS, _MAJOR_COLORS) and boundary definitions (_major_rank_rs_bounds), meaning any changes to these dependencies will directly alter the resulting rank zone configurations without requiring modifications to this function itself.
**Note**: The function assumes that _MAJOR_LABELS and _MAJOR_COLORS contain valid entries for every key returned by _major_rank_rs_bounds(). Missing keys in these dictionaries will raise a KeyError during execution. Since the return value is an immutable tuple, it cannot be modified after creation; any updates to rank configurations must be handled by regenerating the collection. The function does not perform validation on score boundaries or color formats, delegating data integrity checks to the RankZone class and downstream consumers.
**Output Example**: (RankZone(key='bronze_iii', label='Bronze III', rs_min=0, rs_max=100, color='#8B4513'), RankZone(key='silver_iii', label='Silver III', rs_min=300, rs_max=400, color='#C0C0C0'), ...))

## FunctionDef major_rank_key(tier_name)
**major_rank_key**: The function of major_rank_key is to normalize a Tracker tier label into a standardized major tier key for consistent ranking and visualization purposes.
**parameters**: 
· tier_name: A string representing the full tier label (e.g., "Diamond III", "Platinum I") or None.
**Code Description**: The function processes the input tier_name by first validating its presence. It strips surrounding whitespace and converts the string to lowercase. A regular expression removes trailing rank indicators (Roman numerals I, II, III or digits 1, 2, 3) to isolate the core tier name. The cleaned string is then matched against a predefined dictionary named _TIER_ALIASES. If an exact match exists, the corresponding major tier key is returned. If not, the function performs a prefix match against the aliases in the same dictionary and returns the associated key for the first matching alias. If no matches are found, it returns None. Within the project architecture, this function is directly invoked by render_rating_chart to determine which rank zone should be visually emphasized on the rating progression chart. By extracting the major tier from the current tier label, it enables the _draw_rank_zones helper to accurately overlay and highlight the relevant ranking boundaries relative to the player's current standing without requiring exact string matches for every possible rank suffix.
**Note**: The function relies on an external mapping dictionary named _TIER_ALIASES, which must be properly defined in the same module for correct operation. It handles case-insensitivity and flexible rank suffixes but will return None if the input does not align with any registered alias or prefix. Ensure that tier_name contains valid tier data to avoid silent failures in chart rendering logic.
**Output Example**: "Diamond III" -> "diamond", "Platinum I" -> "platinum", "Gold II" -> "gold", None -> None
## FunctionDef zones_intersecting(rs_lo, rs_hi)
**zones_intersecting**: The function of zones_intersecting is to identify and return all major rank zones whose rating score ranges overlap with a specified interval `[rs_lo, rs_hi]`.
**parameters**: The parameters of this Function.
· rs_lo: float - The lower bound of the rating score range to check for intersection.
· rs_hi: float - The upper bound of the rating score range to check for intersection.
**Code Description**: This function filters a global collection of RankZone objects (MAJOR_RANK_ZONES) to determine which tiers intersect with a given rating score window. It first normalizes the input bounds to ensure rs_lo is less than or equal to rs_hi. For each zone, it calculates the effective upper boundary by treating a None value for rs_max as positive infinity. The function then applies interval intersection logic: a zone is excluded only if its entire range lies strictly below rs_lo or strictly above rs_hi. All zones that partially or fully overlap with the target window are appended to a result list and returned. Within the project, this function serves as a critical filtering step for the charting pipeline. It is invoked by _draw_rank_zones in chart.py, which uses the returned list to render background spans, boundary lines, and labels for relevant rank tiers on a matplotlib axis. The caller render_rating_chart passes the vertical axis limits (y_lo, y_hi) derived from player rating data to dynamically highlight only the tiers visible within the current chart viewport.
**Note**: The function assumes that MAJOR_RANK_ZONES is globally defined and contains valid RankZone instances. It treats rs_max == None as an unbounded upper tier, which requires careful handling when comparing against finite floats. The intersection logic uses strict inequalities for exclusion (<= and >=), meaning zones that exactly touch the boundary at a single point are excluded. Callers should ensure that rs_lo and rs_hi represent valid rating score coordinates before invocation.
**Output Example**: [RankZone(key='gold', label='Gold', rs_min=1600, rs_max=1900, color='#FFD700'), RankZone(key='platinum', label='Platinum', rs_min=1900, rs_max=None, color='#E5E4E2')]
## FunctionDef rank_bounds_from_stat_metadata(metadata)
**rank_bounds_from_stat_metadata**: The function of rank_bounds_from_stat_metadata is to extract minimum and maximum rank bounds from a provided metadata dictionary by checking multiple possible key names and safely converting their values to integers.
**parameters**: The parameters of this Function.
· metadata: A dictionary containing potential bound keys or None. It may hold string, float, or integer values associated with various naming conventions for minimum and maximum bounds.
**Code Description**: The function begins by evaluating the truthiness of the input metadata parameter. If metadata is None or an empty collection, the function immediately returns None. When valid metadata is provided, the function iterates through a fixed sequence of four key pairs: tierMin with tierMax, min with max, lowerBound with upperBound, and minValue with maxValue. For each pair, it retrieves the corresponding values from the dictionary using the get method. If both values for a given pair are None, the iteration continues to the next pair. When at least one value is present, the function attempts to cast the values into integers. The lower bound conversion uses an intermediate float step to accommodate string representations of decimal or integer numbers, and it defaults to 0 if the lower key is absent. The upper bound undergoes the same conversion process but retains a None value if its corresponding key is missing. Upon successful conversion, the function returns a tuple containing the computed minimum and maximum bounds. If a TypeError or ValueError occurs during type casting, the exception is caught, and the loop proceeds to the next key pair without interrupting execution. If no valid numeric bounds are found across all predefined key pairs, the function concludes by returning None.
**Note**: The function relies on the presence of specific key names rather than semantic validation, making it compatible with multiple metadata schemas from external trackers. Missing lower bound values are automatically treated as 0, while missing upper bound values remain None. Non-numeric strings or incompatible types will not trigger errors but will cause the current key pair to be silently skipped. The function is strictly designed for numeric extraction and does not perform range validation or boundary clamping.
**Output Example**: (10, 50)
## FunctionDef zone_for_rs(rs)
**zone_for_rs**: The function of zone_for_rs is to identify and return the rank tier configuration that contains a specified integer rank score, or None if the score falls outside all configured tiers.

**parameters**: The parameters of this Function.
· rs: int - The rank score value to be evaluated against the predefined rank zone boundaries.

**Code Description**: This function implements a sequential range lookup mechanism to map an input rank score to its corresponding tier configuration. It iterates through the global MAJOR_RANK_ZONES collection, evaluating each RankZone instance in order. For every zone, it calculates the effective upper boundary by inspecting the rs_max attribute; if this attribute is None, the function substitutes it with positive infinity to represent an unbounded upper limit. The function then verifies whether the input rs satisfies the condition zone.rs_min <= rs < top. Upon finding the first matching zone, it immediately returns that RankZone instance. If the iteration completes without a match, the function applies a fallback evaluation: it checks if the input score meets or exceeds the lower bound of the final zone in MAJOR_RANK_ZONES. If true, it returns the last zone to handle scores that fall into the highest tier or exceed all explicitly bounded upper limits; otherwise, it returns None, indicating the score does not belong to any configured major rank tier. The function directly consumes the structural attributes (rs_min, rs_max) of the RankZone class and relies on the predefined ordering of MAJOR_RANK_ZONES to ensure correct tier resolution. It serves as a central mapping utility that bridges raw integer score inputs with structured zone metadata used throughout the statistics and charting pipeline.

**Note**: The function assumes that MAJOR_RANK_ZONES is populated with non-overlapping, sequentially ordered RankZone instances. It treats the rs_max attribute as exclusive for range comparison purposes, while rs_min is inclusive. If the input score exceeds all defined upper bounds and does not meet the fallback condition for the last tier, the function will return None. The ordering of zones in MAJOR_RANK_ZONES directly impacts lookup correctness, so zones should be arranged in ascending order of their lower bounds. Downstream consumers should handle the None return case appropriately when rendering charts or calculating tier-specific statistics.

**Output Example**: 
RankZone(key="diamond", label="Diamond", rs_min=1000, rs_max=2000, color="#00BFFF")
