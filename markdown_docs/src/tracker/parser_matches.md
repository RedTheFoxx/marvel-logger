## FunctionDef _parse_timestamp(value)
**_parse_timestamp**: The function of _parse_timestamp is to safely convert a raw timestamp string from an API response into a standardized, timezone-aware Python datetime object, returning None for invalid or missing inputs.
**parameters**: The parameters of this Function.
· value: A string representing the timestamp (e.g., "2023-10-25T14:30:00Z" or "2023-10-25T14:30:00+00:00"), or None.
**Code Description**: The function begins by checking if the input value is falsy (None or an empty string). If so, it immediately returns None to prevent parsing errors on missing data. For valid inputs, it attempts to parse the string using datetime.datetime.fromisoformat(). A critical preprocessing step replaces any trailing "Z" character with "+00:00" to ensure compatibility with Python's ISO format parser, as "Z" denotes UTC but is not always natively supported by older Python versions. After parsing, the function verifies whether the resulting datetime object contains timezone information (tzinfo). If tzinfo is None, it explicitly attaches the UTC timezone using datetime.timezone.utc, guaranteeing that all returned datetimes are timezone-aware and consistent. If the input string does not conform to a valid ISO 8601 format, a ValueError is caught, and the function safely returns None instead of crashing.
Functionally, this utility serves as a centralized timestamp normalization layer for the tracker module. It is invoked by parse_match_detail to populate the played_at attribute of individual match records, and by parse_recent_matches to assign the played_at attribute to each entry in a list of recent matches. Both callers depend on this function to transform raw API metadata into reliable datetime objects, which are subsequently used for chronological sorting and UI display formatting without risking runtime exceptions from malformed network responses.
**Note**: Points to note about the use of the code
- The function strictly expects ISO 8601 formatted strings. Non-standard formats will result in a None return.
- All successfully parsed timestamps are normalized to UTC. Downstream consumers should not assume local timezones unless explicitly converted.
- The replacement of "Z" with "+00:00" is a defensive measure for cross-version Python compatibility, particularly relevant in environments running Python 3.6 through 3.10.
**Output Example**: Mock up a possible appearance of the code's return value.
- Input: "2024-05-12T18:45:00Z" -> Output: datetime.datetime(2024, 5, 12, 18, 45, tzinfo=datetime.timezone.utc)
- Input: "2024-05-12T18:45:00+02:00" -> Output: datetime.datetime(2024, 5, 12, 18, 45, tzinfo=datetime.timezone(datetime.timedelta(seconds=7200)))
- Input: None or "invalid-date" -> Output: None

· season_id: int - The identifier for the competitive season associated with the matches.

**Code Description**: This function processes a collection of MatchListEntry instances to extract and structure rating progression data. It is invoked by apply_rating_chart after parse_recent_matches generates the initial MatchListEntry collection. The function ensures data integrity by filtering malformed ratings early and standardizes the dataset size for consistent graph rendering performance.

The capping logic depends on external constants (RATING_GRAPH_MATCH_TARGET and RATING_GRAPH_MATCH_LIMIT) being defined in the module scope; if both are zero or negative, no truncation occurs. The order of points in the returned list preserves the original sequence from the input matches, which is critical for chronological axis mapping in downstream rendering functions. Optional fields like rs_delta and outcome may remain None depending on the source data, requiring consumers to implement null checks before arithmetic or formatting operations. **parameters**: 
· points: list[RatingChartPoint] - A chronological list of ranked match data points, each containing the player's rating score after the match and an optional delta value representing the change for that specific match.

If at least one valid delta exists, it returns the arithmetic sum of these deltas. The calculated delta serves as a summary metric for downstream components, such as chart rendering pipelines and profile statistics modules, enabling efficient visualization of rating evolution without reprocessing individual match entries.
**Note**: The function assumes the input list maintains chronological or sequential order, as the fallback calculation depends on the first and last elements.
